# Final release QA, 29 October 2026

Candidate: `com.khadka.Limitr`, versionCode **12**, versionName **1.3.0**, minSdk 23, compile/target SDK 36, branch `dev-improvements`, PR #4. The owner confirmed Play accepted the replacement upload key. Local QA passes; the Play and physical-device checks below remain before production rollout. No upload or publication was performed.

## Fixed

1. **Opening LIMITR could leave its own blocking overlay covering the screen.** The detector ignored its package's accessibility events to avoid reacting to the overlay itself, which also ignored a real return to LIMITR. An API 36 regression first failed with “Opening LIMITR must dismiss its own blocking overlay.” The service now observes its application's Activity resume callbacks, clears the visible notice and pending rendering, and retains the saved timer. The callback is registered only while connected and unregistered on disconnect. Reopening the selected app still requests Home and blocks it. This uses no extra accessibility capabilities or window-content access.
2. **A delayed Play review request could launch on a later Home visit.** A new test first failed with one unexpected review launch. Leaving the Activity now cancels a request that has not launched. Once Play's review UI has launched, its completion callback retains ownership of the flow. Two passing regressions cover the stale response and pausing for an already launched review. No completion is treated as proof that the user submitted a review.
3. **Obsolete authentication wording remained in rewards.** “First Login Reward” is now “Welcome Reward”; “Daily Login Reward” is now “Daily Reward.” Reward amounts, eligibility and persistence are unchanged.

The owner's intended version 12 / 1.3.0 is recorded in the build configuration. UI edits in this QA pass are exactly the two reward labels above. There are no layout, permission-flow, Room entity, schema or migration changes, and no new dependencies. Referrals remain deferred.

## Risks and suggested work not done

- **Play delivery:** SDK fakes do not render a real review card or prove successful update resumption. Real flexible/immediate updates, priority, downloaded-update restart and account/quota eligibility require internal-track installs. Confirm code 12 is unused in Console; if it was already uploaded, a higher code is required.
- **Production upgrade:** obtain the currently published app through Play and upgrade with existing data. Source-derived Room fixtures cover established historical versions and on-device 13-to-14 migration, but shipped schema samples for versions 5/11 are unavailable. Unknown versions fail closed without deletion. Do not roll out to an unverified shipped schema.
- **Device/runtime coverage:** physical OEM background restrictions, prolonged Doze/reboot, split screen/PiP, and an actual 16 KB runtime remain untested in this pass. Inexact alarms may delay alerts; Android can stop the accessibility service. No new background-service or exact-alarm permission was added.
- **Crypto durability:** existing synchronization/cancellation handling covers ordinary failures; abrupt process death between Room cancellation and DataStore debit still requires a durable cross-store transaction design. This was not expanded into a new schema/refactor during release QA.
- **Lint:** 64 existing resource/style/localization warnings remain visible. No broad resource cleanup or visual redesign was introduced. Gradle 9 deprecation warnings remain on the passing pinned Gradle 8.13 toolchain.
