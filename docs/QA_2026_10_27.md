# App QA, 27 October 2026

This pass checks the current offline app on `dev-improvements`, including the Home/overlay, session-control removal and Help/unblock follow-ups. It preserves UI design and permission flows. No Room entity, schema version, migration, dependency or release identity changes are introduced.

## Fixed

- **Two details screens could unblock two apps using only 2 Crypto.** Each ViewModel checked the same balance before either debit completed. A singleton `CryptoUnblocker` now serializes balance checking, conditional cancellation and spending across screens.
- **Leaving details could cancel a debit after removing the block.** Once cancellation starts, that short local operation now finishes even if its ViewModel is cleared. This does not keep the activity or its views alive.
- **A failed Crypto write left the block removed.** Ordinary debit failures restore the original unexpired row. The recovery keeps its revision, deadline, notification option and history; it ignores an existing replacement and never restores an expired row. A simultaneous Room recovery failure remains a limitation.
- **Timer and interval drafts disappeared on activity recreation.** The activity now saves the open editor and values, including keyboard timer input, the interval's start/end step and the resolved confirmation instants. Cancelled dialogs stay closed; no layout or permission sequence changes are needed.

The Crypto tests reproduced three failures before the fix: two apps removed with one affordable debit, lost debit when the ViewModel was cleared, and missing original timer after a simulated disk write failure. Both editor tests reproduced disappearing dialogs before restoration was implemented.

## Suggested but not done / risk areas

- A durable ledger for atomic Room/DataStore spending. Abrupt process death between stores can still grant a free unblock; full storage failure can prevent compensation. That needs a separately reviewed storage change and migration.
- Production signing-lineage upgrades, actual missing historical database samples, physical OEM background-kill/reboot/Doze tests, long-duration memory/battery measurements and a 16 KB runtime.
- Broad visual/resource lint cleanup, dependency updates and architecture/KSP refactoring. Existing warnings are not hidden by a new baseline.
- At 200% fonts in landscape, the timer's existing "Second" label wraps awkwardly. Controls remain scrollable and usable; the layout was left unchanged under the no-design-change constraint.
- Play Console submission, privacy-policy/declaration updates and old remote-account deletion remain owner actions.

## Manual release checklist

- [ ] Fresh install opens Home without login; disclosure decline/consent, Grant Permission and Continue still work; Help/session controls remain absent.
- [ ] Upgrade a published signed build without clearing data; retain timers, intervals, history, Crypto and settings.
- [ ] Type a timer and rotate before saving; rotate at each interval step and confirmation; saved values remain correct.
- [ ] Insufficient Crypto leaves details and the block intact. Sufficient Crypto debits 2 once, removes the block and finishes details. Repeat with two details screens, rapid taps and background/return.
- [ ] Blocked launches go Home and show one notice covering the status-bar area; Details, Exit and automatic expiry work.
- [ ] Notification hiding affects only selected active apps; ongoing and essential notifications remain. Future intervals begin filtering at their start.
- [ ] Check usage access, history, accessibility reconnect/revoke, lock/unlock, process restart and OEM restrictions.
- [ ] Check landscape, large fonts, cutouts, system navigation, tablets and multi-window/PiP on physical devices.
